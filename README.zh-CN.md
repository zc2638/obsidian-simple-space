# Simple Space · 简洁工作台

[![Attest release assets](https://github.com/zc2638/obsidian-simple-space/actions/workflows/attest-release.yml/badge.svg)](https://github.com/zc2638/obsidian-simple-space/actions/workflows/attest-release.yml)

[English](README.md)

一个清晰、好看、顺手的 Obsidian 工作台。包含欢迎卡片、即时灵感、快捷入口、待办任务、最近笔记和统计卡片。无需 Home Pages、主题或外部 CSS 代码片段。

当前版本为 **0.1.1 内测版**，要求 Obsidian **1.8.7 或以上**。源码和安装包均可在本地生成，尚未发布到社区插件市场。

构建、版本管理、GitHub Release 发布与故障排查见 [发布指南](release.md)。

## 仓库读取与隐私

最近笔记、欢迎区笔记数及全库统计需要通过 Vault API 获取文件路径和元数据；启用字数统计时会读取 Markdown 正文，标签统计使用元数据缓存。目录选择器和配置发现分别检查目录、候选 workspace.json；灵感与待办从文件索引中筛选已配置来源后读取。全库枚举是这些功能的正常读取行为，市场扫描可能继续显示此项权限说明。插件不向外部服务发送笔记、附件或文件路径，不包含遥测；草稿保存在当前设备，外部快捷链接及用户配置的同步服务各自处理其访问与传输。

## 安装与打开

1. 获取 `dist/simple-space-0.1.1.zip`，解压得到 `simple-space` 文件夹。
2. 将整个 `simple-space` 文件夹复制到目标仓库的 `.obsidian/plugins/` 中；没有 `plugins` 目录时先创建。
3. 检查目录层级，下面三个文件应直接位于插件目录内，避免重复嵌套一层 `simple-space`：

   ```text
   仓库/
   └── .obsidian/
       └── plugins/
           └── simple-space/
               ├── main.js
               ├── manifest.json
               └── styles.css
   ```

4. 重启 Obsidian，进入“设置 → 第三方插件”；如处于受限模式，先允许使用第三方插件，再启用 **Simple Space**。
5. 点击左侧工具栏的工作台图标，或打开命令面板，搜索并执行 **Simple Space：打开工作台**。

Mac 在访达中看不到 `.obsidian` 时，按 `⌘ ⇧ .` 显示隐藏文件。命令面板快捷键为 Mac `⌘ P`、Windows `Ctrl P`。

安装仅增加本插件，不替换已有仓库设置。全新安装首次启用时默认使用普通仓库文件 `Simple Space/workspace.json`：已有有效文件时加载，否则创建默认布局，包含六张通用卡片。内容笔记和附件目录仍在第一次实际保存时创建。插件不迁移旧版 Home Pages 配置。

手机端也需要在自己的 vault 安装、启用插件。当前尚未上架，手机安装步骤及录音权限、系统文件选择器需要对应设备真机验收；源码使用跨平台 API，不依赖 Node 文件系统或 macOS 命令。

### 更新已有插件

1. 先保存正在编辑的内容并停止录音，在“设置 → 第三方插件”中禁用 **Simple Space**。
2. 解压新的安装包，只将其中的 `main.js`、`manifest.json`、`styles.css` 覆盖到原来的 `.obsidian/plugins/simple-space/`。
3. 保留原来的 `data.json`（普通目录模式下作为本机配置位置缓存；旧插件目录模式仍保存布局），不要删除或整体替换插件文件夹；`Simple Space/workspace.json`、其他所选配置目录中的 `workspace.json`、内容笔记和附件也应保留。
4. 重新启用 **Simple Space**，即可使用更新后的版本；如界面未刷新，可重启 Obsidian。

## 添加与编辑卡片

- 点击工作台标签页右上角的“添加卡片”（加号），选择六种类型之一；同类型可添加多张。
- 点击卡片齿轮修改标题、宽高、内容来源及其他设置。
- 点击标签页右上角的“编辑布局”（铅笔），展开编辑工具栏；可拖动排序、拖动角标调整大小，或使用卡片底部箭头移动。手机可使用箭头与尺寸表单。
- 手机自动单列显示，卡片和顺序与电脑共用。
- 删除卡片只移除展示，关联笔记、附件及任务保留。存在未保存内容或录音时，先完成保存，再更改来源或删除卡片。

| 卡片 | 可配置内容与默认值 |
|---|---|
| 欢迎 | 名字、引言列表／来源；默认跟随核心日记设置，备用目录 `日记`、格式 `YYYY-MM-DD`、模板留空 |
| 即时灵感 | 默认目录 `Simple Space/即时灵感`、单文件；可选年／季度／月／日及大小续卷 |
| 待办任务 | 默认目录 `Simple Space/待办任务`、单文件；可选年／季度／月／日及大小续卷，可关闭进行中状态 |
| 快捷入口 | 入口标题、地址和列数；默认无入口、2 列 |
| 最近笔记 | 目录、数量、排序及排除目录；默认全仓库、8 篇、最近修改、排除 `工作台配置` |
| 统计 | 笔记数、标签数、字数、附件数的显示开关，默认全部开启，以四格显示 |

所有卡片都能设置类型、标题、宽度和高度，并通过布局排序调整位置。

### 即时灵感

默认显示最近内容，无记录时直接显示创建界面。支持文字、链接、图片、文件、音频、视频及直接录音；桌面支持粘贴及拖入附件。保存快捷键为 Windows `Ctrl + Enter`、Mac `⌘ + Enter`。

默认保存目录为 `Simple Space/即时灵感`，笔记和附件统一放在该目录下。目录可以修改，填 `.` 表示 vault 根目录。

| 保存方式 | 笔记示例 | 对应附件目录 |
|---|---|---|
| 年 | `2026.md` | `附件/2026/` |
| 季度 | `2026-Q4.md` | `附件/2026-Q4/` |
| 月 | `2026-11.md` | `附件/2026-11/` |
| 日 | `2026-11-04.md` | `附件/2026-11-04/` |
| 单文件（默认） | `灵感.md` | `附件/灵感/` |

默认使用单文件 `Simple Space/即时灵感/灵感.md`，附件为 `Simple Space/即时灵感/附件/灵感/`。表中路径均相对于保存目录。单文件名称沿用已有配置中笔记路径的文件名。旧版 `收件箱/灵感.md` 保留为历史来源，不自动搬移或删除；新的保存目标统一位于保存目录内。

默认开启按大小自动续卷，阈值为 **1024 KB（1 MB）**，可在卡片设置中修改或关闭。按 UTF-8 Markdown 文件大小计算，独立图片、音频和其他附件不计入。

例如当月内容达到阈值后，下一卷为 `2026-11-002.md`，其附件对应 `附件/2026-11-002/`。一条灵感始终保持完整；单条本身超限时可以独占一卷，不截断内容。

最近内容跨时间文件、续卷和旧单文件汇总，点击后打开真实来源笔记。保存目标和首次保存时间写入设备草稿，支持失败、异常重开和跨月后的重试查重。

保存报错后继续编辑，会作为新的内容版本保存，已经写入的原记录和附件保留。早期草稿缺少提交版本信息时会保守恢复为待保存内容，可能包含已保存的记录；恢复本身不会自动写入笔记。

未保存草稿及录音片段保存在**当前设备的 IndexedDB**，不会随 iCloud 或插件配置同步。恢复只能恢复已成功写入的文字、附件和完整录音块，不能保证异常终止前最后一瞬间的数据。正式保存后，笔记和附件交给用户已有的同步工具。

直接录音需系统允许 Obsidian 使用麦克风；不支持直接录音时可上传音频。恢复及录音兼容性需要各端实测。

### 欢迎与日记

欢迎卡包含问候、时钟、每日一句和今日台历。点击台历展开完整农历日历；选择日期不创建笔记，点击“打开当日日记”才创建或打开。

默认优先使用核心“日记”插件的目录、日期格式与模板；未配置时使用卡片里的默认设置。模板支持 `{{date}}`、`{{date:格式}}`、`{{time}}`、`{{time:格式}}` 和 `{{title}}`。已有日记不覆盖。

### 待办任务

默认保存目录为 `Simple Space/待办任务`，单文件写入 `Simple Space/待办任务/待办任务.md`，附件位于 `Simple Space/待办任务/附件/待办任务/`。卡片设置与灵感一致：只配置一个保存目录，支持年、季度、月、日和单文件，默认单文件；大小续卷默认 1024 KB，可关闭，独立附件不计入。目录不存在时在实际保存时创建。

看板保留快速添加文字，点击标题栏“创建”可输入多行说明、添加图片或文件、上传音频和视频，以及直接录音。录屏采用上传系统录屏文件。任务正文仍为标准 Markdown 复选框，说明和附件缩进保存在同一任务后；看板按需展开详情，音频和视频不自动播放。实际播放格式由所在设备支持的编解码器决定。

返回看板会停止录音、等待最终片段并备份，重新创建可继续编辑。设备草稿和录音片段使用与灵感相同的 IndexedDB 恢复机制；备份失败时保留编辑器及错误提示。较大媒体依赖设备临时存储容量，容量不足时需检查存储后重试或移除未备份附件，不能将失败提示视为已经保存。

保存目录及子目录中的任务、时间分卷与大小续卷统一汇总，附件目录内的 Markdown 不作为任务来源。旧配置中独立指定的来源笔记／目录仍会读取，新增目标及其续卷也会纳入；不搬移或覆盖旧内容。

完成状态使用标准 `- [x]`，待办使用 `- [ ]`。进行中保存为 `- [ ] 任务 <!-- desk:doing -->`，保持普通 Markdown 里的未完成语义。拖动到状态列或使用任务状态下拉框可修改状态，操作回写原笔记。原任务同步后已变化或无法唯一定位时，拒绝覆盖并提示刷新。

在待办任务卡片的齿轮设置中关闭“显示进行中状态”，看板与状态下拉框就只显示“待办”和“完成”，两列平分可用宽度。已有进行中任务归到待办列展示，关闭开关本身不修改原笔记；重新开启后恢复原状态分列。只有主动拖动或修改任务状态才写回笔记。新卡片与旧配置默认保持进行中状态开启，各张待办卡片可独立设置。

## 配置存储与同步

**全新安装默认使用 `<vault>/Simple Space/workspace.json`**，布局、卡片设置和来源路径均写入这个普通仓库文件；`.obsidian/plugins/simple-space/data.json` 仅保留本设备的配置位置缓存，默认不需要跨设备同步。首次启用时会识别既定路径上的有效配置；不要把文件放在 `.obsidian` 里。

旧安装更新后保留原有存储模式及布局，不自动迁移。要改用推荐位置，请在插件设置选择“仓库目录中的 workspace.json”，目录填 `Simple Space` 并点击“应用存储设置”；若文件已从另一端同步到达，也可通过“发现已有配置”选择它。其他自定义目录同样需要在各端明确选择。

| 所选目录 | 实际配置文件 |
|---|---|
| `Simple Space`（新安装默认） | `<vault>/Simple Space/workspace.json` |
| `.`（仓库根目录） | `<vault>/workspace.json` |
| `工作台配置` | `<vault>/工作台配置/workspace.json` |

目录和配置文件不存在时自动创建，写入当前布局。已有有效配置会被加载，无效文件不会被覆盖。切回插件目录时保留当前布局，原自定义文件不删除。

- 使用默认普通目录 `Simple Space/workspace.json`：交给普通文件同步；官方 Sync 需允许其他文件类型，目录不能被同步规则排除。新安装默认识别此路径，旧安装及其他自定义路径可通过“发现已有配置”选择文件。
- 仅当明确切回“插件配置目录”模式时，布局才使用 `.obsidian/plugins/simple-space/data.json`；官方 Sync 需各端开启相应社区插件配置同步，LiveSync 则需相应的定制同步 DATA 或隐藏文件规则。这个隐藏文件不属于普通文件同步。
- 外部配置到达后自动应用。布局调整不会重建正在输入的灵感；来源变更暂缓到保存完成，避免打断输入与录音。
- 同步文件与插件更新是两回事；安装包更新后需重新加载插件。

插件自身不连接云端服务、不读取同步账号或凭据，不依赖 LiveSync。用户应为同一文件选择一种同步方式。

### 使用 LiveSync 同步插件与布局

推荐先让默认布局 `Simple Space/workspace.json` 跟随 **LiveSync 普通文件同步**，再单独处理插件程序。日常卡片、排序和来源设置的变更不需要每次打开定制同步对话框并点击 Apply。

Self-hosted LiveSync 已提供插件程序同步能力，可选 **Customisation Sync（定制同步／旧界面也称自定义同步）** 或 **Hidden File Sync（隐藏文件同步）**。希望程序更新自动随文件变更传到其他设备，可使用下面的**方式二：隐藏文件同步**；定制同步的手动方式需要在接收端选择并应用。两种方式按程序路径择一配置即可。[官方隐藏文件指南](https://github.com/vrtmrz/obsidian-livesync/blob/main/docs/tips/hidden-file-sync.md)

| 目的 | 需要同步的文件 |
|---|---|
| 安装或更新插件程序 | `.obsidian/plugins/simple-space/main.js`、`manifest.json`、`styles.css`，三者保持同一安装包版本 |
| 同步默认布局、卡片与来源设置 | `Simple Space/workspace.json`，走普通文件同步；不包含插件程序、笔记正文或附件 |
| 其他普通目录配置 | 例如 `工作台配置/workspace.json`，同样走普通文件同步，但各端需选择该位置 |
| 旧／手动选择的插件目录模式 | `.obsidian/plugins/simple-space/data.json`，此模式下才用 DATA 或隐藏文件规则同步布局；默认普通目录模式建议不传这个缓存 |

下述路径假设 Obsidian 配置目录为默认 `.obsidian`；使用自定义配置目录时需对应替换。正式开始前，先让各端普通笔记双向同步正常，备份各端 vault 和已有配置，并指定一台已安装正确版本、布局正确的设备为**首次发布的权威设备**。首次接入期间先只在这台设备修改布局，避免另一端新生成的默认配置反向覆盖已有配置。

以下按 2026-11-04 查阅的官方 `main` 文档整理。不同 LiveSync／Obsidian 版本的中文翻译、分页和按钮位置可能不同；旧教程中的“插件同步”“自定义同步”和新版的 Customisation Sync 应按实际版本核对，不能直接套用旧截图。官方目前将两项列为需要主动开启的高级功能；以所装版本对应文档为准，不为同步本插件单独切换旧版兼容格式。[官方设置说明](https://github.com/vrtmrz/obsidian-livesync/blob/main/docs/settings.md#6-customisation-sync-advanced)

#### 先同步默认布局：普通文件同步

1. 在权威设备确认 Simple Space 使用 `Simple Space/workspace.json`。全新安装默认采用此位置；旧安装按上节手动切换或选择已同步的有效配置。
2. 让 LiveSync 同步该 JSON，检查普通文件筛选、忽略规则及 Obsidian 的“检测所有文件扩展名”设置，确认 `Simple Space/` 未被排除。此步骤不需要开启定制同步 DATA 或隐藏文件同步。[官方文件排查说明](https://github.com/vrtmrz/obsidian-livesync/blob/main/docs/troubleshooting.md)
3. 等文件到达另一端后，再安装／同步并启用插件。新安装会默认识别此文件；旧安装需通过设置切到同一位置。只在一端做一项测试布局变更，待同步完成后检查另一端自动应用，再开始多端日常使用。

以下两种方式用于同步插件程序，与上面的布局文件同步分别配置。

#### 方式一：用定制同步选择插件程序

适合希望在接收端确认程序版本后应用的情况。**同一路径不要再交给隐藏文件同步独立管理**。

1. 各端打开 LiveSync 设置，在 **General Settings → Extra menus → Advanced features** 开启高级功能；旧版可能直接在 General Settings 页显示开关。
2. 找到 **Customisation Sync**，为各端设置不同的设备名并启用。源设备开启 **Scan customisation automatically**（同步前扫描）或周期扫描，再执行一次正常同步并等待完成。
3. 在接收端进入该页，点击 **Open** 打开定制同步对话框；必要时刷新列表。找到 **Simple Space／simple-space**，选择刚才权威设备提供的版本，不要批量应用所有插件和 Obsidian 配置。
4. 选择 **MAIN**（程序）所列的 `main.js`、`manifest.json`、`styles.css`，预览来源和文件后点击 **Apply** 应用。默认普通目录模式不选择 **DATA**，避免同步本机位置缓存；仅当各端明确使用“插件配置目录”模式时，才另选 DATA 中的 `data.json` 传递布局。若列表为空，先确认源端已经扫描、完成同步，再刷新接收端列表。[官方文件分类实现](https://github.com/vrtmrz/obsidian-livesync/blob/main/src/features/ConfigSync/CmdConfigSync.ts)、[官方双仓库验证流程](https://github.com/vrtmrz/obsidian-livesync/blob/main/test/e2e-obsidian/README.md)
5. 收到程序后，按下面“接收端检查”信任、启用并重新加载插件。以后发布新程序，先在权威设备按“更新已有插件”覆盖三个程序文件，再扫描、同步并在其他端应用；默认布局继续由普通文件同步自动传递。

新版对话框若提供 **Automatic**，其含义是将所选文件交给 Hidden File Sync，需先在本设备完成下面方式二的启用与初始化；它不是另一条可叠加的独立同步链路。首次操作建议先按明确的来源选择和 Apply 流程核对文件。[官方 Automatic 说明](https://github.com/vrtmrz/obsidian-livesync/blob/main/docs/tips/hidden-file-sync.md#automatic-in-customisation-sync)

#### 方式二：用隐藏文件同步传递程序文件

适合已有隐藏文件同步方案、希望程序随文件变更同步的情况。默认布局仍走上面的普通文件同步。以下初始化方向仅指 **Hidden Files** 功能，**不要误选整个数据库的重建或覆盖远端操作**。

1. 开启高级功能后，进入 **Selector → Hidden Files**，检查 **Target patterns** 和 **Ignore patterns**。支持目标正则的版本可用下面一条仅放行三个程序文件及必需父目录；不要仅填 `simple-space`，否则扫描可能进不了父目录。

   ```text
   ^\.obsidian(?:$|/plugins(?:$|/simple-space(?:$|/(?:main\.js|manifest\.json|styles\.css)$)))
   ```

   这条规则不包含 `data.json`。若已有宽泛的整目录规则，也要检查它是否仍匹配这个缓存。只有各端明确切回“插件配置目录”模式、需要用隐藏文件同步布局时，才将最后的文件分组改为 `(?:main\.js|manifest\.json|styles\.css|data\.json)`。已有其他隐藏文件同步需求时，应在现有规则上审查调整，不能直接替换后遗漏原有目标。还需确认普通文件部分的 **Non-Synchronising files** 没有排除程序路径；不要清空所有忽略项，也不要把 LiveSync 自身配置纳入本次同步。
2. 权威设备进入 **Sync Settings → Hidden Files → Enable Hidden File Sync**，首次选 **Overwrite**：以这台设备的隐藏文件为准写入远端。保持 Obsidian 开启，等待扫描、上传完成。
3. 其他端分别检查同样的目标及忽略规则，再在同一功能中选择 **Fetch**：将已经上传的远端版本应用到本机。只有双方都有要保留的隐藏文件修改时才考虑 **Merge**，并逐项处理冲突；不要仅凭“更新时间较新”决定保留哪份配置。
4. 等待应用完成，按提示重启 Obsidian，再做“接收端检查”。各端需分别启用隐藏文件同步；普通连接设置导入、数据库恢复并不代表它已开启。后续可按所装版本配置同步前扫描或周期扫描，并用一次更新验证实际传输。[官方隐藏文件完整指南](https://github.com/vrtmrz/obsidian-livesync/blob/main/docs/tips/hidden-file-sync.md)

#### 接收端检查

- 确认接收端 `.obsidian/plugins/simple-space/` 中有同版本的三个程序文件；在 Obsidian 提示信任仓库／第三方插件时确认信任，然后到“设置 → 第三方插件”启用 **Simple Space**。同步文件不等于已允许执行插件；不要依赖同步另一端的启用列表。
- 已运行旧版本时，等待文件同步完成后禁用再启用 Simple Space；仍未刷新时重启 Obsidian。用打开工作台、检查插件版本及一项测试布局变更验证结果，再接入下一台设备。
- 确认各端选用同一个布局文件。默认是 `Simple Space/workspace.json`；新安装默认识别既定路径，旧安装保留原模式，需要手动切换或通过“发现已有配置”选择。无需同步普通目录模式的 `data.json` 位置缓存。
- Simple Space 的 `Simple Space/workspace.json` 与 Obsidian 自己的 `.obsidian/workspace.json` 不同；前者不含程序、正文、附件或设备草稿。内容笔记和附件仍需正常同步，设备 IndexedDB 草稿不随 LiveSync 迁移。
- 首次出现冲突先保留备份，确认权威设备、来源及配置位置，再按 LiveSync 和本插件各自的冲突提示处理；不要删除配置文件或反复双向覆盖来试错。这里未对用户的 LiveSync 服务、账号或各端设备做实际同步验收。

## 配置冲突和分享

配置包含格式版本、修订历史与卡片定义。检测到多端分叉时保留两份，通过提示或“处理工作台配置冲突”命令选择本机或同步版本。设备私有备份不会跟随仓库同步。同步工具本身产生的文件冲突仍需按该工具的流程处理。

处理冲突期间若另一端改变配置存储位置，会保留旧冲突并刷新新位置的预览；请检查窗口中的当前配置位置，再确认使用哪个版本。

“导出配置”可预览 JSON 并保存到仓库指定路径，不覆盖已有文件；文件只包含布局、卡片设置和来源路径，不包含笔记正文或附件。“导入配置”须先预览，再确认替换布局；导入后可能需要调整来源路径以匹配目标 vault。

## 开发

```sh
npm ci
npm test
npm run build
npm run package
```

`npm run build` 生成 `main.js`；`npm run package` 生成含 `main.js`、`manifest.json`、`styles.css`、说明及许可的安装 ZIP。生产环境只依赖 Obsidian，测试和构建依赖不随包分发。

完整需求见 [设计文档](docs/superpowers/specs/2026-11-04-workspace-plugin.md)。单元及 DOM 集成测试覆盖配置来源、冲突、任务回写、设备草稿、录音恢复及卡片生命周期；四端实际安装、文件选择器、麦克风权限与视觉效果仍需真机验收。测试通过不代表已完成跨设备同步验收。
